1

한 줄 요약

모델 학습은 이 열한 단계 중 하나일 뿐이다. 그리고 이 파이프라인은 한 번 흐르고 끝나는 직선이 아니라, 모니터링 → 재학습으로 되돌아오는 고리다.

학습 목표

  1. 열한 단계를 순서대로 나열하고, 각 단계가 무엇을 입력받아 무엇을 내놓는지 말할 수 있다.
  2. 검증과 평가를 구분하고, 왜 둘을 분리해야 하는지 설명할 수 있다.
  3. 재학습 주기 $T^{*} = \sqrt{2C/(k\delta)}$ 를 유도하고 실제 숫자를 넣어 계산할 수 있다.
2

직관

입문자가 흔히 그리는 그림은 이렇다 — 데이터를 넣고, 모델을 학습시키고, 끝. 실제로 돌아가는 시스템에서 모델 학습 코드가 차지하는 비중은 아주 작다. Sculley 등은 이를 두고 "ML 코드는 전체 시스템의 작은 상자 하나에 불과하다"고 지적했다1. 나머지는 데이터 수집·검증·서빙·모니터링 같은 주변 인프라다.

더 중요한 차이가 하나 있다. 이 파이프라인은 끝나지 않는다. 세상이 변하면 모델이 낡는다. 그래서 모니터링이 재학습을 부르고, 고리가 다시 돈다.

3

형식적 정의

파이프라인은 함수 합성으로 쓸 수 있다. 1.1절의 딥러닝 정의와 같은 형식이다.

$$ \hat{y} \;=\; \bigl(h_{\theta^{*}} \circ \phi \circ \rho\bigr)(x_{\text{raw}}) $$
(1)

원자료 $x_{\text{raw}}$ 가 전처리 $\rho$, 특성 표현 $\phi$, 학습된 모델 $h_{\theta^{*}}$ 를 차례로 통과한다. 학습할 때와 추론할 때 이 합성이 정확히 같아야 한다 — 이것이 지켜지지 않는 것이 실무의 가장 흔한 버그다.

준비 단계

데이터 수집 — 무엇을 모을지가 곧 무엇을 배울지를 정한다. 수집 과정의 편향은 나중에 어떤 알고리즘으로도 지울 수 없다. "어떤 표본이 빠졌는가"를 묻는 것이 이 단계의 핵심이다.

데이터 전처리 $\rho$ — 결측 처리, 이상치 제거, 중복 제거, 스케일 조정. 여기서 쓰는 통계량(평균·표준편차 등)은 반드시 훈련 데이터에서만 계산해야 한다. 검증·테스트 데이터를 포함해 계산하면 정보가 새어 든다(1.5절 데이터 누출).

특성 표현 $\phi$ — 원자료를 모델이 다룰 수 있는 벡터로 바꾼다. 전통적으로는 사람이 설계했고(feature engineering), 딥러닝은 이 단계를 학습으로 대체한다. 그래도 완전히 사라지지는 않는다 — 토큰화, 정규화, 창 나누기는 여전히 사람이 정한다.

모델 선택 — 가설 공간을 고르는 일이다. 1.1절에서 구분한 대로 모델은 무엇을 표현할 수 있는가를 정한다. 하이퍼파라미터 탐색도 여기에 속하며, 검증 데이터로 판단한다.

학습과 검증

학습 — $\theta^{*} = \arg\min_\theta \frac{1}{n}\sum L$. 훈련 데이터만 쓴다.

검증 — 학습 중에 선택을 하기 위해 쓴다. 어느 하이퍼파라미터가 나은가, 언제 멈출까(early stopping), 어느 모델을 채택할까. 검증 데이터는 여러 번 본다.

평가 — 모든 선택이 끝난 뒤 단 한 번 성능을 재기 위해 쓴다. 테스트 데이터를 보고 모델을 고치면, 그 순간 테스트 데이터는 검증 데이터가 되어 버린다.

검증과 평가의 차이

같은 "성능 측정"처럼 보이지만 목적이 다르다. 검증은 고르기 위해, 평가는 보고하기 위해 잰다. 검증 점수는 여러 번 최적화의 대상이 되므로 낙관적으로 치우친다. 그래서 편향 없는 추정치를 얻으려면 손대지 않은 테스트 집합이 따로 필요하다.

운영 단계

추론 — 학습된 $\theta^{*}$ 로 새 입력에 답한다. 학습과 달리 지연시간·처리량·비용이 제약이 된다. 같은 모델도 배치 추론이냐 실시간이냐에 따라 설계가 달라진다.

배포 — 모델을 실제 서비스에 올린다. 버전 관리, 점진적 롤아웃, 문제 시 되돌리기(rollback)가 필요하다. 학습 때의 전처리 $\rho, \phi$ 를 그대로 재현하는 것이 핵심 과제다.

모니터링 — 예측 품질, 입력 분포, 지연시간, 오류율을 지켜본다. 정답이 늦게 오거나 아예 안 오는 경우가 많아, 정답 없이도 이상을 감지하는 장치가 필요하다 (입력 분포 변화 감시 등).

재학습 — 성능이 떨어지면 새 데이터로 다시 학습해 배포한다. 얼마나 자주 할지는 감이 아니라 계산으로 정할 수 있다. 아래에서 유도한다.

4

수식과 기호

재학습 주기를 정하는 문제를 세운다. 모델은 배포 직후가 가장 좋고, 시간이 지나면 성능이 떨어진다. 자주 재학습하면 비용이 들고, 드물게 하면 성능 손실이 쌓인다.

$$ \text{일일 총비용}\quad J(T) \;=\; \underbrace{\frac{C}{T}}_{\text{재학습 비용}} \;+\; \underbrace{\frac{k\,\delta\,T}{2}}_{\text{성능 손실 비용}} $$
(2)

성능이 하루에 $\delta$ 만큼 선형으로 떨어진다면, 주기 $T$ 동안 평균 저하량은 $\delta T / 2$ 다 (0에서 $\delta T$ 까지 고르게 늘어나므로 평균은 절반). 여기에 저하 한 단위의 비용 $k$ 를 곱했다.

유도 — 최적 재학습 주기

$$ J(T) = \frac{C}{T} + \frac{k\delta}{2}\,T $$
식 (2). 앞항은 $T$ 가 커지면 줄고, 뒷항은 커진다 — 상충한다
$$ \frac{dJ}{dT} = -\frac{C}{T^{2}} + \frac{k\delta}{2} $$
$C/T = CT^{-1}$ 의 미분은 $-CT^{-2}$, 뒷항은 상수 곱이라 그대로
$$ \frac{C}{T^{2}} = \frac{k\delta}{2} $$
최솟값에서 도함수는 0. 두 항을 같게 놓았다
$$ T^{2} = \frac{2C}{k\delta} $$
양변에 $T^{2}$ 을 곱하고 $k\delta/2$ 로 나눴다
$$ \boxed{\;T^{*} = \sqrt{\frac{2C}{k\delta}}\;} $$
$T > 0$ 이므로 양의 제곱근만 취한다
이 식이 말해주는 것

제곱근이 핵심이다. 재학습 비용 $C$ 가 4배가 되어도 주기는 2배만 길어진다. 비용이 비싸다고 재학습을 무한정 미루는 것이 최적이 아니라는 뜻이다. 반대로 성능이 빨리 낡는 영역($\delta$ 가 큰 곳 — 예: 추천, 이상탐지)에서는 주기가 $1/\sqrt{\delta}$ 로 짧아진다.

정말 최솟값인가 — 2계 도함수

$\dfrac{d^2J}{dT^2} = \dfrac{2C}{T^{3}} > 0$ ($T>0$, $C>0$). 2계 도함수가 양수이므로 $J$ 는 아래로 볼록이고, $T^{*}$ 는 유일한 전역 최솟값이다. 1.1절의 최소제곱 유도와 같은 논법이다.

6

손으로 푸는 예제

추천 모델을 운영한다고 하자. 관측된 값은 이렇다.

  • 재학습 1회 비용 $C = 100$ (만원) — GPU 시간과 검증 인건비
  • 정확도가 하루에 $\delta = 0.1$ %p 씩 떨어진다
  • 정확도 1%p 하락은 하루 $k = 2$ (만원)의 매출 손실
$$ k\delta = 2 \times 0.1 = 0.2 $$
하루 늦출 때마다 추가로 생기는 손실의 기울기
$$ \frac{2C}{k\delta} = \frac{2 \times 100}{0.2} = \frac{200}{0.2} = 1000 $$
유도한 식의 제곱근 안쪽을 먼저 계산
$$ T^{*} = \sqrt{1000} \approx 31.6\ \text{일} $$
약 한 달에 한 번. 감이 아니라 계산으로 나온 값이다
$$ J(T^{*}) = \frac{100}{31.6} + \frac{0.2 \times 31.6}{2} = 3.16 + 3.16 = 6.32 $$
최적점에서 두 비용이 정확히 같아진다 — 유도 3단계가 그 뜻이었다

다른 주기와 비교하면 최적점의 의미가 분명해진다.

성능이 선형으로 떨어진다고 가정했다. 실제로는 계단식으로 떨어지거나 (제품 개편, 계절 변화), 한동안 멀쩡하다가 급락하기도 한다. 또 $\delta$ 를 미리 안다고 가정했지만, 현실에서는 모니터링으로 추정해야 한다.

그래도 이 식은 쓸모가 있다. 주기를 정하는 근거를 숫자로 만들고, "재학습 비용을 절반으로 줄이면 주기가 $\sqrt{2}$ 배 짧아진다" 같은 판단을 가능하게 한다. 모형이 틀렸다는 것과 쓸모없다는 것은 다르다.

8

흔한 오해와 함정

오해 1

"파이프라인은 한 번 흐르면 끝이다."

실제로는 고리다. 세상이 변하면 데이터 분포가 변하고, 모델은 가만히 있어도 낡는다. 모니터링 → 재학습 → 배포로 되돌아오는 화살표가 없으면 그것은 실험이지 시스템이 아니다.

오해 2

"검증 데이터와 테스트 데이터는 사실상 같다."

실제로는 역할이 다르다. 검증은 고르기 위해, 평가는 보고하기 위해 쓴다. 검증 점수를 보고 하이퍼파라미터를 100번 조정했다면 그 점수는 이미 낙관적으로 편향돼 있다. 테스트 점수를 보고 모델을 고치는 순간, 테스트 집합도 같은 운명이 된다.

오해 3

"전처리는 사소한 준비 작업이다."

실제로는 식 (1)의 $\rho, \phi$ 는 모델의 일부다. 학습 때와 서빙 때 이 함수가 다르면 모델이 아무리 좋아도 결과가 무너진다(학습·서빙 왜곡). 그래서 전처리를 코드로 한 곳에 묶어 학습·서빙이 같은 경로를 쓰게 만드는 것이 표준 관행이다.

오해 4

"성능이 떨어지면 무조건 재학습하면 된다."

실제로는 원인을 먼저 나눠야 한다. 입력 분포가 변한 것(covariate shift)이라면 새 데이터 재학습이 맞지만, 데이터 파이프라인이 깨진 것이라면 재학습은 오염된 데이터를 학습하는 셈이 되어 더 나빠진다. 모니터링이 "성능"만이 아니라 입력 분포와 데이터 품질을 함께 봐야 하는 이유다.

코드로 확인

NumPy — 최적 재학습 주기 (12줄) 
import numpy as np

C, delta, k = 100.0, 0.1, 2.0          # 비용, 일일 저하, 저하 단가

T_star = np.sqrt(2 * C / (k * delta))
print(T_star)                           # 31.6227766...  = √1000

J = lambda T: C / T + k * delta * T / 2
print(J(T_star))                        # 6.3245553...

# 수치적으로도 확인 — 격자 탐색의 최소가 같은 자리에 있는가
grid = np.linspace(1, 200, 20000)
print(grid[np.argmin(J(grid))])         # 31.62...  ✓

# 최적점에서 두 비용이 같아진다
print(C / T_star, k * delta * T_star / 2)   # 3.162... 3.162...

자가 점검

계산 $C = 200$, $k\delta = 0.4$ 일 때 $T^{*}$ 는?

풀이 · $T^{*} = \sqrt{2 \times 200 / 0.4} = \sqrt{400/0.4} = \sqrt{1000} \approx 31.6$. 본문 예제와 같은 값이다 — $C$ 와 $k\delta$ 가 둘 다 2배가 되어 비율이 유지됐기 때문이다.

계산 재학습 비용 $C$ 만 9배로 늘면 최적 주기는 몇 배가 되는가?

풀이 · $T^{*} \propto \sqrt{C}$ 이므로 $\sqrt{9} = 3$ 배. 제곱근이라 비용이 크게 늘어도 주기는 완만하게만 길어진다.

개념 전처리에 쓸 평균과 표준편차는 어느 데이터에서 계산해야 하는가?

풀이 · 전체에서 계산하면 검증·테스트의 정보가 훈련 과정에 새어 든다(데이터 누출). 테스트 성능이 실제보다 좋아 보이게 되어, 배포 후에 성능이 떨어진다.

개념 식 (1)에서 배포 시 가장 자주 깨지는 부분은?

풀이 · 가중치는 파일로 그대로 옮겨지지만, 전처리는 학습 코드(예: 파이썬 노트북)와 서빙 코드(예: 자바 서비스)에 따로 구현되기 쉽다. 이 둘이 어긋나는 것이 학습·서빙 왜곡이다.

함정 다음 중 틀린 진술은?

풀이 · 나가 틀렸다. 데이터 파이프라인이 깨져서 성능이 떨어진 경우, 재학습은 오염된 데이터를 학습하게 되어 오히려 악화된다. 가는 유도 3단계에서 확인했고(예제에서 3.16 = 3.16), 다는 검증과 평가의 정의다.
