1

한 줄 요약

chain rule(연쇄법칙)은 Jacobian을 곱하는 일이고, 그 곱을 어느 쪽부터 계산하느냐가 forward mode와 reverse mode를 가른다. loss가 숫자 하나라서 뒤에서부터가 압도적으로 싸며, 그것이 backpropagation(역전파)이다.

학습 목표

  1. 계산 그래프를 그리고 forward pass(순전파)와 backward pass를 손으로 한 스텝씩 계산할 수 있다.
  2. reverse mode가 forward mode보다 싼 이유를 행렬 곱의 순서 비용으로 설명할 수 있다.
  3. 노드가 여러 곳으로 갈라질 때 gradient를 더하는 이유를 다변수 chain rule로 설명할 수 있다.
2

직관

환율을 생각한다. 원 → 달러가 $1/1400$ 이고 달러 → 엔이 $150$ 이면, 원 → 엔은 두 비율의 곱이다. chain rule 이 하는 일이 정확히 이것이다 — "$x$ 가 1 변하면 $u$ 가 얼마나 변하고, $u$ 가 1 변하면 $y$ 가 얼마나 변하는가"를 곱한다.

비율이 여러 단계면 곱도 여러 개다. 그런데 곱셈의 순서는 자유다. 앞에서부터 곱해도 되고 뒤에서부터 곱해도 결과는 같다. 하지만 비용은 전혀 다르다 — 이것이 이 절의 핵심이다. 입력이 $10^9$ 개, 출력이 1 개인 딥러닝에서는 뒤에서부터가 $10^9$ 배 싸다.

핵심

backpropagation은 새로운 수학이 아니다. chain rule + 곱셈 순서를 잘 고른 것이다. "역전파 알고리즘"이라는 이름 때문에 특별해 보이지만, 하는 일은 이미 계산해 둔 중간값에 미분을 하나씩 곱하며 거꾸로 걸어 나오는 것뿐이다.

3

형식적 정의

Function Composition & Chain Rule 함수 합성과 연쇄법칙

$$ y = g(f(x)) \;\Longrightarrow\; \frac{dy}{dx} = \frac{dy}{du}\cdot\frac{du}{dx}, \qquad u=f(x) $$
(1)

합성함수의 변화율은 각 단계 변화율의 곱이다. 3.1에서 정의한 합성 $g\circ f$ 를 미분하는 규칙이며, Leibniz 표기에서는 $du$ 가 약분되는 것처럼 보인다 — 실제로 약분은 아니지만 결과가 맞아 이 표기가 살아남았다.

다변수·벡터값으로 확장하면 3.3의 식 (9)가 된다.

$$ \mathbf{y}=\mathbf{f}_L(\mathbf{f}_{L-1}(\cdots \mathbf{f}_1(\mathbf{x}))) \;\Longrightarrow\; \mathbf{J} = \mathbf{J}_L\,\mathbf{J}_{L-1}\cdots\mathbf{J}_1 $$
(2)

바깥 함수가 왼쪽이다. 이 곱을 왼쪽부터 계산하면 reverse mode, 오른쪽부터 계산하면 forward mode다. 결과는 같고 비용만 다르다.

Computation Graph 계산 그래프

정의

node(노드)는 변수 또는 연산, edge(엣지)는 의존 관계인 방향 비순환 그래프(DAG)로 계산을 표현한 것. 어떤 값이 어떤 값으로부터 만들어졌는지가 그래프의 모양에 담긴다.

복잡한 식을 원시 연산(primitive)의 조합으로 쪼갠 것이 계산 그래프다. 예를 들어 $L=(\sigma(wx+b)-y)^2$ 은 다음 다섯 노드로 쪼개진다.

노드연산국소 미분
$u = wx$곱$\partial u/\partial w = x$, $\partial u/\partial x = w$
$z = u+b$합$\partial z/\partial u = 1$, $\partial z/\partial b = 1$
$a = \sigma(z)$sigmoid$\partial a/\partial z = a(1-a)$
$d = a-y$차$\partial d/\partial a = 1$
$L = d^2$제곱$\partial L/\partial d = 2d$

각 노드는 자기 국소 미분만 알면 되고, 전체 미분은 그 국소 미분들을 이어 곱해 만든다. 이것이 자동미분이 임의로 복잡한 model 에서도 동작하는 이유다 — 새 층을 추가할 때 그 층의 국소 미분 하나만 등록하면 나머지는 그래프가 알아서 한다.

Forward Pass 순전파

그래프를 위상 순서대로 훑으며 각 노드의 값을 계산하고, backward 에서 필요할 중간값을 저장하는 단계다. 위 예에서 $w=0.5,\ x=2,\ b=-1,\ y=1$ 이면 $u=1$, $z=0$, $a=0.5$, $d=-0.5$, $L=0.25$ 가 차례로 나온다.

저장이 공짜가 아니다. $a$ 를 저장해 두어야 $\partial a/\partial z = a(1-a)$ 를 다시 계산하지 않는데, 층이 깊고 batch 가 크면 이 중간값(activation)이 GPU 메모리를 대부분 차지한다. gradient checkpointing 은 일부러 저장을 포기하고 backward 때 다시 계산해 메모리와 시간을 맞바꾸는 기법이다.

Reverse Differentiation 역방향 미분

각 노드 $v$ 에 adjoint(수반값) $\bar{v} = \dfrac{\partial L}{\partial v}$ 를 하나씩 둔다. 출력에서 $\bar{L}=1$ 로 시작해 거꾸로 전파한다.

$$ \bar{v} = \sum_{w \in \text{children}(v)} \bar{w}\,\frac{\partial w}{\partial v} $$
(3)

"내 뒤에 오는 노드들의 adjoint에 국소 미분을 곱해서 전부 더한다" — backpropagation 전체가 이 한 줄이다. vector 로 쓰면 VJP(vector–Jacobian product)가 된다.

$$ \bar{\mathbf{v}}^\top = \bar{\mathbf{w}}^\top \mathbf{J}_{\mathbf{w}/\mathbf{v}} \qquad (\text{VJP}) $$
(4)

중요한 것은 $\mathbf{J}$ 를 실제로 만들지 않는다는 점이다. linear layer의 Jacobian은 $\mathbf{W}$ 이므로 VJP 는 그냥 $\mathbf{W}^\top\bar{\mathbf{w}}$ 이고, 원소별 activation의 Jacobian은 대각행렬이라 VJP 는 $\odot$ 한 번이다. $(n,n)$ matrix를 메모리에 올리는 일이 없다.

쉬운 말로

forward 는 재료가 요리가 되는 과정, backward 는 "이 요리가 짠 건 누구 탓인가"를 거슬러 묻는 과정입니다.

맨 끝에서 "짜다"라고 판정하면, 바로 앞 단계에 "네가 얼마나 기여했나"를 묻고, 그 단계는 다시 자기 앞 단계에 같은 질문을 넘깁니다. 한 재료가 두 군데에 들어갔으면 두 몫을 합쳐서 책임을 묻습니다 — 그것이 식 (3)의 합 기호입니다.

Automatic Differentiation 자동미분

미분을 구하는 방법은 셋이고, 자동미분은 그중 수치 오차 없이 프로그램 그대로 미분하는 방법이다.

방법하는 일정확도비용문제
수치 미분$\dfrac{f(x+h)-f(x)}{h}$근사 ($O(h)$)파라미터당 1회 평가느리고 반올림 오차
기호 미분수식을 대수적으로 변형정확식이 지수적으로 팽창제어 흐름·반복문을 못 다룸
자동미분원시 연산의 미분을 chain rule 로 조합정확 (반올림만)forward 의 상수배메모리(중간값 저장)

자동미분이 기호 미분과 다른 점은 수식이 아니라 값을 다룬다는 것이다. $\frac{d}{dx}$ 의 결과로 "$2x$" 라는 식을 만드는 대신 "$x=3$ 에서 $6$" 이라는 수를 낸다. 그래서 if 문과 반복문이 섞인 프로그램도 그대로 미분할 수 있다 — 실행된 경로가 곧 그래프이기 때문이다1.

Reverse Mode vs Forward Mode

식 (2)의 곱 $\mathbf{J}_L\cdots\mathbf{J}_1$ 을 어느 쪽부터 계산하느냐의 차이다. 행렬 곱은 결합법칙이 성립하므로 결과는 같지만 연산 횟수가 다르다.

곱하는 순서오른쪽부터 $(\cdots(\mathbf{J}_L(\mathbf{J}_2\mathbf{J}_1)))$왼쪽부터 $(((\mathbf{J}_L\mathbf{J}_{L-1})\cdots)\mathbf{J}_1)$
기본 연산JVP $\mathbf{J}\mathbf{v}$ (Jacobian–vector)VJP $\mathbf{u}^\top\mathbf{J}$ (vector–Jacobian)
한 번에 얻는 것입력 한 방향에 대한 모든 출력의 미분출력 하나에 대한 모든 입력의 미분
전체 Jacobian 비용입력 개수 $n$ 회출력 개수 $m$ 회
메모리작다 (값과 함께 전진)크다 (중간값 전부 저장)
유리한 경우$n \ll m$ (입력이 적을 때)$m \ll n$ — 딥러닝이 여기

딥러닝은 입력(파라미터)이 $10^9$ 개, 출력(loss)이 1 개다. reverse mode 는 단 한 번의 backward로 $10^9$ 개 gradient를 전부 얻고, forward mode 는 같은 일에 $10^9$ 번의 forward 가 필요하다. 비용 차이가 $10^9$ 배다.

forward mode 가 쓸모없다는 뜻은 아니다. Hessian-vector product $\mathbf{Hv}$ 를 forward-over-reverse 로 계산하면 Hessian을 만들지 않고도 곡률 정보를 얻을 수 있고, JAX 의 jvp 가 이 용도로 쓰인다.

Gradient Accumulation 기울기 누적

한 변수가 여러 곳에 쓰이면(fan-out) 경로마다 gradient가 오고, 그것을 전부 더한다. 식 (3)의 합 기호가 이것이고, 근거는 다변수 chain rule 이다.

$$ L = h(p(x),\, q(x)) \;\Longrightarrow\; \frac{dL}{dx} = \frac{\partial L}{\partial p}\frac{dp}{dx} + \frac{\partial L}{\partial q}\frac{dq}{dx} $$
(5)

residual connection $\mathbf{y}=\mathbf{x}+F(\mathbf{x})$ 이 정확히 이 구조다 — $\mathbf{x}$ 가 두 경로로 갈라지므로 gradient가 $\bar{\mathbf{y}} + \bar{\mathbf{y}}\mathbf{J}_F$ 로 합쳐진다. 첫 항 $\bar{\mathbf{y}}$ 가 아무것도 곱해지지 않은 채 그대로 흘러가는 것이 ResNet 이 깊어져도 gradient가 죽지 않는 이유다.

같은 이름, 다른 뜻

실무에서 "gradient accumulation" 은 다른 뜻으로도 쓰인다 — GPU 메모리가 모자라 batch 를 여러 micro-batch 로 쪼개 backward 를 여러 번 돌리고 optimizer.step() 을 한 번만 하는 기법이다. 이 경우 .grad 에 값이 누적되는 성질을 이용하는 것이라 이름이 같다.

PyTorch 에서 optimizer.zero_grad() 를 매 스텝 호출해야 하는 이유도 여기 있다 — 프레임워크는 gradient를 덮어쓰지 않고 더한다. 이 절의 fan-out 규칙과 micro-batch 기법이 같은 메커니즘을 공유한다.

5

유도

유도 1 — 곱셈 순서가 비용을 바꾼다

$\mathbb{R}^{n}\to\mathbb{R}^{p}\to\mathbb{R}^{m}$ 인 두 층을 생각하자. Jacobian 은 $(p,n)$ 과 $(m,p)$ 다.

$$ \mathbf{J} = \mathbf{J}_2\mathbf{J}_1, \qquad \mathbf{J}_2\in\mathbb{R}^{m\times p},\ \mathbf{J}_1\in\mathbb{R}^{p\times n} $$
전체 Jacobian은 $(m,n)$
$$ \text{비용}(\mathbf{J}_2\mathbf{J}_1) = m\,p\,n $$
행렬 곱의 표준 비용. 전체를 다 만들면 이만큼 든다
$$ m=1 \;\Longrightarrow\; \bar{\mathbf{u}}^\top\mathbf{J}_2 \ \text{는 } 1\cdot p \text{ 짜리 행벡터} $$
loss 는 scalar 라 왼쪽 인자가 행벡터다
$$ (\bar{\mathbf{u}}^\top\mathbf{J}_2)\mathbf{J}_1: \quad 1\!\cdot\!m\!\cdot\!p + 1\!\cdot\!p\!\cdot\!n = p(m+n) $$
reverse mode. 행벡터를 유지하며 왼쪽부터 곱했다
$$ \mathbf{J}_2(\mathbf{J}_1\mathbf{v}): \quad p\!\cdot\!n\!\cdot\!1 + m\!\cdot\!p\!\cdot\!1 = p(m+n) \ \text{— 방향 하나당} $$
forward mode. 같은 비용이지만 입력 방향 하나만 얻는다
$$ \text{전체 gradient: reverse } m\times p(m{+}n) \ \text{ vs forward } n\times p(m{+}n) $$
$m=1$, $n=10^9$ 이면 $10^9$ 배 차이
한 줄로

reverse 는 출력 개수만큼, forward 는 입력 개수만큼 훑는다. 딥러닝은 출력이 1(loss)이고 입력이 수십억(파라미터)이라 reverse 가 이긴다. 반대로 입력이 하나고 출력이 많은 문제(예: 초기조건 하나에 대한 궤적 전체의 민감도)에서는 forward 가 이긴다.

유도 2 — fan-out 에서 왜 더하는가

$$ p = p(x), \quad q = q(x), \quad L = h(p, q) $$
$x$ 가 두 경로로 갈라진 그래프
$$ L(x+\Delta) \approx h\bigl(p+p'\Delta,\ q+q'\Delta\bigr) $$
$x$ 를 흔들면 $p$ 와 $q$ 가 동시에 흔들린다
$$ \approx h(p,q) + \frac{\partial h}{\partial p}p'\Delta + \frac{\partial h}{\partial q}q'\Delta $$
$h$ 의 1차 근사 (3.3 식 7의 1차항)
$$ \frac{L(x+\Delta)-L(x)}{\Delta} \to \frac{\partial h}{\partial p}p' + \frac{\partial h}{\partial q}q' $$
두 기여가 더해진다 — 곱해지는 것이 아니다
$$ \bar{x} = \bar{p}\,\frac{\partial p}{\partial x} + \bar{q}\,\frac{\partial q}{\partial x} $$
adjoint 표기로 쓰면 식 (3) 그 자체

유도 3 — residual connection 이 gradient 를 지키는 이유

$$ \mathbf{y} = \mathbf{x} + F(\mathbf{x}) $$
$\mathbf{x}$ 가 두 경로(직행 · $F$ 통과)로 간다
$$ \frac{\partial\mathbf{y}}{\partial\mathbf{x}} = \mathbf{I} + \mathbf{J}_F $$
항등 경로의 Jacobian 은 $\mathbf{I}$
$$ \bar{\mathbf{x}} = (\mathbf{I}+\mathbf{J}_F)^\top\bar{\mathbf{y}} = \bar{\mathbf{y}} + \mathbf{J}_F^\top\bar{\mathbf{y}} $$
식 (3)의 합. 첫 항이 손상 없이 통과한다
$$ L \ \text{개 쌓으면} \quad \prod_{\ell}(\mathbf{I}+\mathbf{J}_{F_\ell}) = \mathbf{I} + \sum_\ell \mathbf{J}_{F_\ell} + \cdots $$
전개하면 $\mathbf{I}$ 항이 살아남는다
$$ \text{residual 없음: } \prod_\ell \mathbf{J}_\ell \;\to\; \mathbf{0} \ \text{ 또는 } \infty $$
곱만 있으면 2.7의 $\rho^L$ 거동 — 지수적으로 사라지거나 폭발
forward mode 를 dual number 로 구현하기

$\epsilon^2=0$ 인 기호 $\epsilon$ 을 도입해 수를 $a+b\epsilon$ 꼴로 확장한다(dual number). 그러면 곱셈이 이렇게 된다.

$(a+b\epsilon)(c+d\epsilon) = ac + (ad+bc)\epsilon + bd\epsilon^2 = ac + (ad+bc)\epsilon$.

$\epsilon$ 의 계수를 보면 곱의 법칙 $(uv)'=u'v+uv'$ 이 그대로 나온다. $x$ 자리에 $x+1\cdot\epsilon$ 을 넣고 프로그램을 그냥 실행하면, 결과의 $\epsilon$ 계수가 $f'(x)$ 다. 코드를 한 줄도 고치지 않고 연산자 오버로딩만으로 forward mode 자동미분이 구현되는 이유이며, 이 우아함 때문에 교과서가 forward mode 를 먼저 소개한다. 다만 딥러닝에서는 입력이 너무 많아 실용성이 떨어진다.

6

손으로 푸는 예제

$L=(\sigma(wx+b)-y)^2$ 을 $w=0.5,\ x=2,\ b=-1,\ y=1$ 에서 계산하고, $\partial L/\partial w$ 와 $\partial L/\partial b$ 를 손으로 구한다. 숫자가 전부 깔끔하게 떨어진다.

① Forward Pass

$$ u = wx = 0.5\times2 = 1 $$
곱 노드
$$ z = u+b = 1+(-1) = 0 $$
합 노드
$$ a = \sigma(0) = \frac{1}{1+e^0} = \frac12 = 0.5 $$
sigmoid 노드. 이 값을 저장해 둔다 — backward 에서 쓴다
$$ d = a-y = 0.5-1 = -0.5 $$
차 노드
$$ L = d^2 = (-0.5)^2 = 0.25 $$
제곱 노드 — 최종 loss

② Backward Pass — 뒤에서부터

$$ \bar{L} = \frac{\partial L}{\partial L} = 1 $$
언제나 1 로 시작한다
$$ \bar{d} = \bar{L}\cdot\frac{\partial L}{\partial d} = 1\times 2d = 2(-0.5) = -1 $$
$L=d^2$ 이므로 국소 미분이 $2d$
$$ \bar{a} = \bar{d}\cdot\frac{\partial d}{\partial a} = -1\times1 = -1 $$
$d=a-y$ 이므로 국소 미분이 1 — 덧셈·뺄셈은 gradient 를 그대로 통과시킨다
$$ \bar{z} = \bar{a}\cdot a(1-a) = -1\times 0.5\times0.5 = -0.25 $$
저장해 둔 $a$ 를 재사용. $\sigma$ 를 다시 계산하지 않는다
$$ \bar{u} = \bar{z}\times1 = -0.25, \qquad \bar{b} = \bar{z}\times1 = -0.25 $$
$z=u+b$ — 합 노드는 gradient 를 양쪽에 복사한다
$$ \bar{w} = \bar{u}\cdot\frac{\partial u}{\partial w} = -0.25\times x = -0.25\times2 = -0.5 $$
$u=wx$ — 곱 노드는 gradient 에 상대편 값을 곱한다
$$ \bar{x} = \bar{u}\cdot w = -0.25\times0.5 = -0.125 $$
입력에 대한 gradient — 이전 층으로 넘어갈 값이다

③ 검산 — 수치 미분과 비교

$$ w = 0.501 \;\Rightarrow\; z = 0.501\times2-1 = 0.002 $$
$w$ 만 $h=0.001$ 만큼 키웠다
$$ a = \sigma(0.002) \approx 0.5005,\quad d \approx -0.4995,\quad L \approx 0.2495 $$
$\sigma(0.002)\approx0.5+0.25\times0.002$
$$ \frac{0.2495-0.25}{0.001} = \frac{-0.0005}{0.001} = -0.5 \ \checkmark $$
backward 로 얻은 $\bar{w}=-0.5$ 와 일치
$$ \text{한 걸음: } w \leftarrow 0.5-0.1(-0.5) = 0.55,\quad b \leftarrow -1-0.1(-0.25) = -0.975 $$
$\eta=0.1$ 로 gradient descent
$$ z = 0.55\times2-0.975 = 0.125,\ \ a\approx0.5312,\ \ L\approx(0.5312-1)^2 \approx 0.2198 $$
$0.25 \to 0.2198$ 로 줄었다 ✓ 목표인 $y=1$ 쪽으로 갔다

④ Fan-out — 한 변수가 두 번 쓰일 때

$f(x) = x^2 + 3x$ 를 계산 그래프로 보면 $x$ 가 두 갈래로 나간다.

$$ p = x^2, \qquad q = 3x, \qquad f = p+q $$
$x=2$ 에서 $p=4$, $q=6$, $f=10$
$$ \bar{f}=1 \;\Rightarrow\; \bar{p} = 1, \quad \bar{q} = 1 $$
합 노드는 복사
$$ \text{경로 1: } \bar{p}\cdot\frac{dp}{dx} = 1\times2x = 4 $$
$x=2$ 대입
$$ \text{경로 2: } \bar{q}\cdot\frac{dq}{dx} = 1\times3 = 3 $$
두 번째 갈래
$$ \bar{x} = 4+3 = 7 $$
더한다. 공식으로도 $f'=2x+3=7$ ✓
$$ \text{경로 1 만 쓰면 } 4 \ (\text{틀림}), \quad \text{곱하면 } 12 \ (\text{틀림}) $$
덮어쓰기 버그와 곱셈 착각이 각각 이 두 값을 만든다

⑤ 비용 비교 — 실제 숫자로

문제입력 $n$출력 $m$forward modereverse mode승자
딥러닝 학습10⁹110⁹ 회1 회reverse
$f:\mathbb{R}\to\mathbb{R}^{1000}$ 민감도110001 회1000 회forward
$3\times3$ Jacobian 전체333 회3 회메모리가 적은 forward

표의 첫 줄이 딥러닝 전체를 가능하게 만든 계산이다. 파라미터가 몇 개든 backward 한 번이면 전부 얻는다 — 이 성질이 없었다면 수십억 파라미터 model 은 학습 자체가 불가능했을 것이다.

7

직접 조작해 보기

본문의 위젯 — 계산 그래프 · 비용 비교 · fan-out — 을 만져 본 뒤, 아래에서 자동미분과 수치 미분의 정확도 차이를 확인한다. 수치 미분은 $h$ 를 줄여도 어느 지점부터 더 나빠진다.

8

흔한 오해와 함정

오해 1

"자동미분은 수치 미분이다."

실제로는 완전히 다르다. 자동미분은 $h$ 를 쓰지 않으며, 각 원시 연산의 정확한 미분 공식을 chain rule 로 조합한다. 오차는 부동소수점 반올림뿐이라 수치 미분보다 $10^8$ 배 정확하다(마지막 위젯). "auto"라는 이름 때문에 근사처럼 들리지만, 실은 손으로 미분한 것과 같은 값을 낸다.

오해 2

"reverse mode 가 언제나 낫다."

실제로는 출력이 적을 때만 낫다. 입력 1 개에 출력 1000 개인 문제에서는 forward 가 1000배 싸다(예제 ⑤). 그리고 reverse 는 중간값을 전부 들고 있어야 해 메모리를 많이 쓴다 — 긴 sequence 나 깊은 model 에서 OOM 이 나는 주된 원인이며, gradient checkpointing 으로 시간과 맞바꾼다.

오해 3

"fan-out 노드의 gradient 는 곱한다."

실제로는 더한다(유도 2, 예제 ④). 직렬로 이어진 경로는 곱하고, 병렬로 갈라진 경로는 더한다 — 직렬은 곱, 병렬은 합이라고 외우면 헷갈리지 않는다. 직접 backward 를 구현할 때 이 규칙을 어기면 residual connection 이나 multi-head attention 처럼 갈라지는 구조에서 gradient 가 조용히 틀린 값이 된다.

오해 4

"zero_grad() 는 형식적인 호출이다."

실제로는 빠뜨리면 이전 스텝의 gradient 가 그대로 남아 더해진다. 프레임워크가 덮어쓰지 않고 누적하는 것은 fan-out 규칙(식 3)을 그대로 구현했기 때문이며, 같은 성질을 이용해 micro-batch 를 여러 번 돌리는 기법이 실무의 gradient accumulation 이다. 기본 동작이 "누적"이라는 것을 알면 두 이야기가 하나로 이해된다.

오해 5

"계산 그래프는 미리 정해진 고정 구조다."

실제로는 PyTorch 같은 define-by-run 프레임워크에서는 실행하면서 그래프가 만들어진다. if 문의 분기나 반복 횟수가 입력에 따라 달라지면 그래프도 달라진다 — 그래도 자동미분은 문제없이 동작한다. 실행된 경로만이 그래프이기 때문이다. 반대로 기호 미분은 이런 프로그램을 다룰 수 없고, 이것이 자동미분이 딥러닝의 표준이 된 실질적 이유다.

9

코드로 확인

예제 ①–④ 를 20줄짜리 자동미분 엔진으로 직접 구현한다. 외부 라이브러리 없이 동작한다.

Python — 최소 reverse-mode 자동미분 (20줄) 
import math

class V:                                   # 값 + adjoint + 역전파 훅
    def __init__(s, d, kids=(), back=lambda: None):
        s.d, s.g, s.kids, s._b = d, 0.0, kids, back
    def __add__(s, o):
        out = V(s.d + o.d, (s, o)); out._b = lambda: (add(s, out.g), add(o, out.g)); return out
    def __sub__(s, o):
        out = V(s.d - o.d, (s, o)); out._b = lambda: (add(s, out.g), add(o, -out.g)); return out
    def __mul__(s, o):
        out = V(s.d * o.d, (s, o)); out._b = lambda: (add(s, o.d*out.g), add(o, s.d*out.g)); return out
    def sig(s):
        a = 1/(1+math.exp(-s.d)); out = V(a, (s,)); out._b = lambda: add(s, a*(1-a)*out.g); return out

def add(v, x): v.g += x                    # <- 덮어쓰지 않고 '더한다' (fan-out 규칙)
def backward(root):
    topo, seen = [], set()
    def walk(v):
        if id(v) in seen: return
        seen.add(id(v)); [walk(k) for k in v.kids]; topo.append(v)
    walk(root); root.g = 1.0
    for v in reversed(topo): v._b()

w, x, b, y = V(0.5), V(2.0), V(-1.0), V(1.0)
d = (w*x + b).sig() - y;  L = d*d
backward(L)
print(L.d, w.g, b.g, x.g)   # 0.25 -0.5 -0.25 -0.125   <- 예제 ①②와 정확히 일치

add() 가 += 인 것이 이 구현의 핵심이다 — 이 한 글자가 fan-out 규칙(식 3)이고, $x^2+3x$ 처럼 변수가 두 번 쓰이는 식도 자동으로 맞는 값을 낸다. Karpathy 의 micrograd 가 같은 구조를 100줄로 확장한 것이다.

자가 점검

계산 예제와 같은 그래프에서 $\bar{z}=-0.25$, $x=2$ 일 때 $\bar{w}$ 는?

풀이 · $u=wx$ 이므로 $\partial u/\partial w = x = 2$, 따라서 $\bar w = -0.25\times2 = -0.5$. 나는 $\bar{x} = \bar{u}\cdot w = -0.25\times0.5$ 로 상대편을 바꿔 곱한 값이다. 곱 노드는 "gradient 에 상대편 값을 곱한다"가 규칙이다.

계산 $f(x)=x^2+3x$ 를 계산 그래프로 미분하면 $x=2$ 에서 $\bar{x}$ 는?

풀이 · $x$ 가 두 경로로 갈라지므로 더한다 — $2x + 3 = 4+3 = 7$(예제 ④). 나는 병렬 경로를 곱한 오답, 다는 한 경로만 쓰고 다른 경로를 덮어쓴 오답이다. 직접 구현할 때 v.g = ... 로 쓰면 다가 나오고, v.g += ... 로 써야 가가 나온다.

개념 입력 $n=10^6$, 출력 $m=1$ 일 때 전체 gradient 를 얻는 비용은?

풀이 · reverse 는 출력 개수만큼, forward 는 입력 개수만큼 훑는다(유도 1). 출력이 1 개(loss)이므로 reverse 는 한 번이면 끝난다. 다는 정확히 반대로 기억한 것이며, 이 방향을 헷갈리면 "왜 딥러닝이 backprop 을 쓰는가"의 답이 뒤집힌다.

개념 forward pass 에서 중간값 $a=\sigma(z)$ 를 저장하는 이유는?

풀이 · sigmoid 의 국소 미분이 출력만으로 표현되므로 $a$ 만 있으면 다시 계산할 필요가 없다(예제 ②). 이 저장이 GPU 메모리의 큰 부분을 차지하며, gradient checkpointing 은 일부러 버리고 backward 때 다시 forward 를 돌려 메모리를 아낀다. "시간과 메모리의 교환"이 바로 여기서 생긴다.

개념 residual connection $\mathbf{y}=\mathbf{x}+F(\mathbf{x})$ 의 backward 는?

풀이 · $\mathbf{x}$ 가 두 경로로 갈라지므로 더한다(유도 3). 첫 항 $\bar{\mathbf{y}}$ 가 아무것도 곱해지지 않은 채 통과하는 것이 깊은 model 에서도 gradient 가 죽지 않는 이유다. 나는 항등 경로를 빠뜨린 것으로, 이것이 곧 residual 없는 평범한 층이다.

함정 수치 미분에서 $h$ 를 $10^{-15}$ 로 줄이면?

풀이 · $f(x+h)$ 와 $f(x)$ 가 거의 같은 값이라 뺄셈에서 유효숫자가 대량으로 소실된다(catastrophic cancellation). float64 에서 최적 $h$ 는 대략 $10^{-8}$ 근처이고, 그보다 작으면 반올림 오차가 지배한다. 이 문제가 아예 없는 것이 자동미분의 장점이며, 마지막 위젯에서 V 자 곡선으로 확인할 수 있다.
